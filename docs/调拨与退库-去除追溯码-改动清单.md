## 〇、先对齐 3 个口径

1. **"退库" = `stock-return`**（科室 / 成员机构把药退回上级药库），不是 `drug-return` 药品退货（退给供应商）。后者在需求里明确要求录追溯码（`docs/库存管理-药品退货-需求整理.md` 第 13 条），本清单**不动它**。
2. 追溯码在这两个模块里**只出现在"出库执行 / 入库执行"环节**。建单页（`transfer-create` / `transfer-h-create` / `stock-return-create`）、审核页、列表页**一处都没有**，无需改动。
3. 本次只删「展示 + 采集 + 校验」，**建议保留数据字段**（`traces` / `verified` / `badCodes` 等），否则历史单据打开会报错、`sessionStorage` 里的旧数据也会崩。详见 §5。

## 四、需要你拍板的 5 个决策（会影响 §2.2 / §3.1 的具体写法）

**决策 1 · 入库数量从哪来？**（追溯码没了，"扫码即数量"的机制失效）
- **A（推荐）**：默认带出调拨/退库数量，可改；改动即视为差异，必须填差异原因（少发/多发/破损）。好处：保留差异追溯能力，操作最省。
- **B**：锁定为调拨数量，不可改；只允许填「不合格数量 + 原因」。好处：最简单；坏处：真实少发场景无法记录。
- **C**：全手工录入，校验 ≤ 调拨数量。好处：最贴近纸质流程；坏处：每单都要敲数字。

**决策 2 · 「不合格数量 + 不合格原因」保留吗？**
现在它挂在"标记不合格码"上。建议保留为独立字段（数量 + 原因下拉），与追溯码解耦——这样破损/包装不合格仍可在签收时登记。若一并砍掉，入库流程只剩"确认收货"，差异全部线下处理。

**决策 3 · 出库侧还要不要"数量必须等于申请量"的约束？**
原来由"扫码数量 = 出库数量"隐式保证。建议：出库数量 **≤ 申请数量** 即可，允许少发（差额在入库时体现），不允许超发。

**决策 4 · 旧单据字段怎么处理？**
建议：字段保留、页面不展示、`normalize` 不再自动生成。这样 `sessionStorage` 里已有的 `TRANSFER_DATA` / `SR_DATA` 不会因为字段缺失而报错。

**决策 5 · 药品退货（`drug-return`）要不要一起去掉？**
需求文档明确要求"参考出库页录入追溯码、不强制录满"，与本次"退库"是两回事。**建议不动**，除非你确认要一起改。

## 六、最容易漏的 6 个坑

**6.1 `colspan` 全部要减 1**（不做会出现表格错位，但不会报错，肉眼才发现）
- `transfer-inbound.html`：L275 `12` → `11`、L286 `8` → `7`、L305 `13` → `12`
- `transfer-detail.html`：L240 `7` → `6`、L292 `12` → `11`、L315 `8` → `7`、L330 `8` → `7`
- `stock-return-detail.html`：列由 `cols` 数组动态拼，无硬编码，安全

**6.2 `styles.css` 的固定列规则会错位**（★ 最容易漏）
`styles.css` L3034-3041（注释在 L3033）用 `nth-last-child(2)` 把「追溯码核对」列固定在右侧 `right:96px`。删掉该列后，这条规则会落到「零售价金额合计」上，导致数据列被钉在右边。必须同步删除这段规则（`last-child` 的"操作列固定"要保留）。`transfer-inbound` 和 `transfer-detail` 都用了 `.tr-in-tree`，两页同时受影响。

**6.3 文案/提示/toast 散落在 8 处**
除表头外还有：`transfer-outbound` L88、L403 扫码说明、L463 "已自动补齐"、`transfer-inbound` L91、L452/L456/L499 文案、`stock-return-detail` L476/L499/L763。建议改完 `grep -n "追溯\|扫码"` 复核到 0。

**6.4 `.tr-code-progress` 不能跟着删**
`outbound-create.html`、`drug-return-create.html` 仍在用这个类（styles.css L2885-2887）。同理 `.tr-code-chip` / `.trv-*` 建议先留着，等这两块也确认废弃再清理 CSS。

**6.5 审批记录的 `opinion` 文案**
`stock-return-detail` L511-518 会拼"少发 X、非本单码 X"进审批记录。这类文本会进入历史数据，改之前要决定新产品口径（建议："入库单号 + 不合格 X（线下处理）"，差异用数量表达）。

**6.6 页签滚动 / 空态兜底**
`transfer-detail` L329-331、`transfer-inbound` L305 的空态 `colspan` 与列数强绑定；删列时容易只改表头忘改空态。
